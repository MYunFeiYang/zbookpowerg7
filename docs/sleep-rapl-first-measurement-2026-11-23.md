# 首次睡眠期 RAPL 直接功耗分解（2026-11-23 18:00-18:24）

> 目的：回答一个悬了十几轮的问题——**3.6W 睡眠功耗到底是不是"卡包级 C3"造成的，CPU 占多少**。
> 此前所有归因都是推断；本次是第一次用硬件能量计数器直接测出分项。

## 1. 测量条件

| 项 | 值 |

| 睡眠方式 | `Clamshell Sleep:TCPKeepAlive=disabled`（合盖） |
| 入睡 | 18:00:26 |
| 唤醒 | 18:23:45（`Wake from Deep Idle [CDNVA] due to PWRB/UserActivity`） |
| pmset 实测睡眠 | **1399 s（23.3 min）** |
| RAPL 采样窗口 | 17:59:51 → 18:24:01 = **1450 s** |
| 过渡/清醒段 | 1450 − 1399 = **51 s**（入睡前 35s + 唤醒后 16s） |
| 期间 DarkWake | 无（一次睡到底，无中途唤醒） |

## 4. 纯睡眠期分解（中心值，PKG 2.057 W）

| 部件 | 功率 | 占 PKG |
|---|---|---|
| core (PP0) | **1.121 W** | 54.5% |
| DDR | **0.566 W** | 27.5% |
| uncore（余量） | **0.362 W** | 17.6% |
| GT 核显 (PP1) | **0.008 W** | 0.4% |

**GT = 0.008W 是决定性的一条**：核显在睡眠期功耗几乎为零 ⇒ **确实进了 RC6**（把旧结论从 ~85% 提到 >95%，且这次是睡眠当次实测，不是清醒态外推）。

## 5. 交叉验证：powerlog 独立佐证（>99%）

`/var/db/powerlog/Library/BatteryLife/CurrentPowerlog.PLSQL` 的
`PLMacCPUGPUAgent_EventBackward_PackageEnergyCState` 表：

- `PkgCState3Residency`：ID88（17:48:38）= 602 → ID89（18:23:52）= 1,375,392
- **Δ = 1,374,790**
- 本次 RAPL 算出的 PKG_C3 增量 = **1,374,800**

两个完全独立的来源（Apple powerlog vs 直读 MSR）差 10 个计数 ⇒ **TSC 换算（ticks ÷ 2.592GHz）正确**，此前"residency ÷ 1e9 当纳秒"的 bug 修正确认（原算法会虚高 2.592 倍）。

同表还自洽：`PkgCanyResidency 1,574,843 = PkgCState2 199,451 + PkgCState3 1,375,392`。

## 6. 整机功耗：本次无法算（电池计量局限）

| 时刻 | mAh | RawLevel |
|---|---|---|
| 17:59:44（睡前最后一条） | 5601 | 97.65% |
| 18:23:31（唤醒瞬间） | 5594 | 97.52% |
| 18:23:35（4 秒后） | 5442 | 94.87% |

只掉 7 mAh，随后 4 秒掉 152 mAh ⇒ **电池计量芯片在 S0ix 期间停更、唤醒后一次性补偿跳变**。23 分钟短睡的量级被补偿跳变完全掩盖，**短睡整机瓦数不可信**。

另外 `pmset` 百分比在本机不可用：显示 100% 时 `RawLevel` 只有 97.77%，`DesignCapacity 7170` vs `MaxCapacity 5736` ⇒ 电池健康度已降到 **80%**，且 1% 只对应约 30 mAh（非线性）。**必须用 ioreg 的 mAh**。

整机功耗仍引用历史长睡数据（points.jsonl 四组 3.612-3.700W，极差 0.088W）。

## 7. 结论：3.6W 的归因（首次定量）

- **CPU 封装 2.06W / 整机 3.6W = 57%**
- **非 CPU 部分 1.54W**（PCH、SSD、屏关闭态、EC、雷电控制器、电池转换损耗等）

所以"卡 C3 = 3.6W"这个旧表述**部分成立**：CPU 是最大单项（57%），但**不是全部**。还有 1.54W 在 CPU 之外，那部分即使进了 C6/C10 也省不掉。

## 8. "进 C6 值多少"的定量答案（推断，<80%）

core 在 C3 状态吃 1.12W。按 Intel 规格，C3→C6 主要靠 VR 降压 + 时钟域关断，core 功耗可降到 C3 的 30-50%：

| 假设 | PKG | 整机 | 节省 |
|---|---|---|---|
| core 降到 50% | 1.50 W | 3.04 W | 0.56W（16%） |
| core 降到 30% | 1.27 W | 2.81 W | 0.79W（22%） |

**即：解决 C6 的收益约 0.6-0.8W（整机降 16-22%），不是数量级改善**（不是 3.6W→1W）。这解释了为什么十几轮的各种尝试收效有限——即使全成功，天花板也在 2.8-3.0W。

把握度 <80%：C3/C6 功耗比来自 Intel 规格推断，未在本机实测（需要真进 C6 才能测）。

## 9. 工具缺陷记录（第 6、7 项）

- **缺陷 6**：采集只记 pmset 百分比（1% 粒度 + 充电上限钳制 + 电池健康 80%），无法算整机。已改为同时记录 `ioreg` 的 `CurrentCapacity/MaxCapacity/Voltage/InstantAmperage`。
- **缺陷 7**：`ioreg` 输出是 `"Key" = value`（等号带空格），原正则 `"Key"=value` 只匹配到嵌套字典里的无空格形式，导致 CurrentCapacity/MaxCapacity 抓不到。已加 ` ?= ?` 容错并 `sed` 统一。
- 新增**过渡期剔除**：从 `pmset -g log` 取 `Entering Sleep ... N secs`，把 51s 清醒段按三档假设扣掉，输出区间。
